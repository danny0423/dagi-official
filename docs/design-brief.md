# 設計任務：前台畫面

給負責畫面設計的 AI。開工前依序讀：`AGENTS.md` → `docs/site-architecture.md` → `docs/tech-architecture.md` 第 4 節。

## 任務

把 `app/(site)/` 底下 13 個佔位頁做成完整畫面，加上全站共用的頁首與頁尾。後台 `/admin` 不在這次範圍內。

**完成條件**：13 頁的每一個區塊都依照 `docs/site-architecture.md` 的順序出現，文案照抄該文件；畫面在 375px 手機寬與 1440px 桌機寬都正常；`npx eslint .` 通過。

## 風格：清水模（D14）

沉穩、有質感，像建築作品集。對象是建設公司、政府招標審查人員、危老地主，他們要看到的是「可靠、專業、有分量」。

| 項目 | 方向 |
|---|---|
| 色彩 | 以清水模的灰階為主（淺灰底、中灰分隔、近黑文字），加一個克制的強調色只用在 CTA 與重點。不沿用 隆磐 品牌色（D15）。強調色先提 2～3 個候選給使用者挑，再套用 |
| 字體 | 繁體中文用思源黑體（Noto Sans TC）：大標用粗重字重、內文用一般字重；數字對齊用等寬數字（`tabular-nums`） |
| 版面 | 大量留白、大標題、清楚的網格；區塊之間用大間距而不是框線區隔 |
| 質感 | 清水模的質感用 CSS 做（灰階漸層、細微雜訊紋理），不用圖片檔 |
| 動態 | 只用淡入、輕微位移這類安靜的效果；尊重 `prefers-reduced-motion` |

## 圖片：目前沒有任何真實照片

公司還沒提供自家工地照（`docs/content-collection.md` #13）。營造業網站用素材網的工地照會被誤認為自家工程，所以：

- 所有照片位置都用一個共用的「照片佔位」元件：清水模質感底色＋置中的 `【待填：照片說明】` 文字＋固定長寬比。
- 版面要在全部都是佔位圖的狀態下看起來就完整、好看；之後換成真實照片時只需要換圖，不需要改版面。
- 圖片一律用 `next/image`，並寫好 `alt`。

## 待填資料的呈現

- 文案中的 `【待填：…】`、`【範例專案，非真實案件】` 要原樣顯示，並加上明顯的標記樣式（例如淡黃底），讓任何人一眼看出這是還沒填的資料。
- 統編、登記證字號、公司名稱等公司資料，之後會從資料庫的 `company_settings` 讀（`docs/tech-architecture.md` F6）。現在先集中寫在一個常數檔（例如 `lib/placeholder-company.ts`），所有頁面從這裡取，之後換成資料庫只要改一處。

## 技術規則

- Tailwind CSS v4 已裝好；設計 token（顏色、字級、間距）寫在 `app/globals.css` 的 `@theme`。
- 共用元件放 `components/`。預設用 Server Component，只有真的需要互動的元件（例如手機選單）才加 `"use client"`，前台要維持 SEO。
- 每頁的 `metadata` 已經有 title，保留；有需要再補 `description`。
- CTA 按鈕加上 `data-cta="位置名稱"`（例如 `hero`、`footer`），之後 GA4 事件 G5 要用。
- 電話用 `tel:` 連結、Email 用 `mailto:` 連結（GA4 事件 G3、G4 要用）。
- 無障礙：文字對比達 WCAG AA、可以只用鍵盤操作、有可見的 focus 樣式。
- 改完只跑 `npx eslint .`；要啟動 dev server、跑 build、或 commit 之前先問使用者。

## 建議順序

1. 先做 `app/globals.css` 的設計 token＋頁首頁尾＋首頁，給使用者看過、同意風格後再繼續。
2. 再做其餘 12 頁。
3. 最後逐頁對照 `docs/site-architecture.md`，確認每個區塊都在、順序正確、沒有自己編出任何事實。
