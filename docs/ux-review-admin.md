# 後台 UI／UX 審查（`app/admin/`）

2026-10-02｜impeccable critique（A 設計審查、B 偵測器各由獨立 subagent 執行）＋ Playwright 實際操作 6 條流程｜截圖：`review-screens/admin/`（1366px／375px，共 109 張）

## 總評

- 沒有 P0；P1 有 10 項（#1～#10），P2 有 21 項。Nielsen 啟發式 22/40（Acceptable），認知負荷檢查表 8 項中 5 項不及格。
- 最嚴重的是資料遺失：登入過期後送出表單會變成英文錯誤頁、內容全部消失（#1）；離開未存檔的表單也沒有任何提醒（#2）。
- 行政人員最常卡在三處：網址代稱要手打英文（#4）、送出失敗後找不到是哪一欄錯（#3）、表單裡上傳的圖片被提示「到媒體庫補替代文字」（#7）。
- 手機版的列表與收件匣，主要操作都在畫面外（#5）。
- 已經做到的部分：刪除與停用都有確認、驗證失敗時保留已填內容、未同意公開的成員伺服器端擋住不能上架、EDITOR 進不了管理頁（`61-editor-denied`）。

## 任務流程

步驟從儀表板開始算，每次點擊、輸入或選檔各算 1 步。

| 流程 | 步驟數 | 卡點 |
|---|---|---|
| 新增工程實績、上傳封面並上架 | 最少 7／實測 11 | 網址代稱打中文被擋（#4）；出錯後畫面停在頁底，錯誤欄位在上方約 630px 外（#3）；封面無法在表單裡填替代文字（#7）；上架後沒有前台連結可以確認（#31） |

| 新增團隊成員（含同意公開） | 最少 7／實測 11 | 先勾「上架」再勾「同意」會被擋；同意日期非必填（#18） |

| ADMIN 建立 EDITOR 帳號 | 7 | 初始密碼由 ADMIN 自己訂，對方之後沒地方改（#6） |
| EDITOR 試圖進帳號管理 | 1（直接輸入網址） | 會被導回儀表板並顯示「權限不足」，這部分正確；但沒寫要找誰申請，也沒有「我的帳號」頁（`/admin/account` 是英文 404，#6、#24） |
